## Why this matters

Four nontrivial dependencies are declared in the **root** `package.json` but
imported by nothing in the root source tree (`app/`, `components/`, `lib/`,
`hooks/`, `src/`). One is a native-addon package with per-platform binaries
(`@oh-my-pi/pi-natives`, pinned at major **15**, while the backend uses major
13), one is a full alternative router (`react-router-dom`) that misleads
contributors about how routing works (the app uses Next's router). They inflate
`bun install`, the lockfile, CI time, `npm audit` noise, and supply-chain
surface for zero benefit.

## Current state

Verified with grep at the planned-at commit — **zero** import sites in
`app/ components/ lib/ hooks/ src/` for each of:

- `package.json:25` — `"@oh-my-pi/pi-natives": "^15.10.10"` (the backend has its
  own copy at `^13.19.0` inside `testeiya/node_modules`; the root copy is unused).
- `package.json:32` — `"@testomatio/mcp": "^2.1.1"` (legitimately used only
  inside `testeiya/`, not the root UI).
- `package.json:49` — `"prop-types": "^15.8.1"`.
- `package.json:53` — `"react-router-dom": "^7.17.0"` (the app routes via
  `next/navigation`, e.g. `app/page.tsx:73`).

The repo uses **Bun** (`bun.lock` present; `engines.bun >= 1.3.5`). There is no
`package-lock.json`/`npm`. The desktop build ships `testeiya/node_modules`
separately (`electrobun.config.ts`), so removing these root deps does not affect
the backend.
